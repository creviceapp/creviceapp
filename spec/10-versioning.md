## 10. Versioning

### 10.1 Version Source

Build workflows resolve a four-part version string before compilation or packaging. Workflow dispatch accepts an explicit version input. Tag-triggered workflows derive the version from the tag. Untagged workflow dispatch falls back to `4.14.<run-number>.0`.

### 10.2 Version Application

`.github/scripts/Set-Version.ps1` applies the resolved version to `CreviceApp` assembly metadata and `CreviceAppPackage/Package.appxmanifest`, then exposes `CREVICE_VERSION` to later workflow steps.

Release artifact names and Store package metadata use `CREVICE_VERSION`.

The `Crevice.Core` NuGet package version is supplied to `nuget pack` from `CREVICE_VERSION`.

### 10.3 Tags

Tag-triggered release workflows publish artifacts for the pushed tag. The GitHub release zip workflow creates or updates the GitHub Release for the tag.

### 10.4 Artifact Names

Store upload artifacts use the workflow artifact name `crevice-store-upload-<version>`.

Release zip artifacts use the workflow artifact name `crevice-unsigned-zip-<version>`. Section 9 defines the zip filename.

### 10.5 Version Consistency

A release version identifies the source revision, Store upload package, direct-download zip, and checksum generated by the same workflow run.
